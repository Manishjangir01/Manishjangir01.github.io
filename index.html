Big Data Analytics Pipeline

A PySpark job that cleans and validates ride records, writes partitioned Parquet, answers questions with Spark SQL and loads PostgreSQL.

202,000 rows read, 189,369 clean, 10,631 rejected

Python, PySpark, Apache Spark, SQL, PostgreSQL, Docker Compose

Built with guidance from an AI mentor.

What is inside
  • Reads every column as text first, so bad values are not changed silently.
  • 8 validation rules. Rejected rows keep their raw values and a reason.
  • Spark SQL queries: daily revenue, busiest hours, top pickup zones, payment mix, best zone per day.
  • Tests compare the Spark output with the independent pandas version. GitHub Actions runs them with real Spark and a PostgreSQL service.

Automated Web Scraping Pipeline

Scrapes book listings from a practice site, validates them and stores them in SQLite without creating duplicates.

Second run on the same data adds 0 new rows

Python, requests, BeautifulSoup, SQL, SQLite, pytest, GitHub Actions

Built with guidance from an AI mentor.

What is inside
  • Reads robots.txt, waits between requests, and retries timeouts and 429/5xx errors with backoff.
  • Saves the raw data first, then applies 5 validation rules. Rejected records keep a reason.
  • Stores a price-history row only when a price changes. Every run is marked ok, partial, failed or empty.
  • 44 tests run against a local copy of the site's page markup. A weekly workflow runs the real scraper.

DataFlow ETL Studio

A no-code ETL web app: pull data from a REST API or an uploaded file, clean and validate it step by step, and load it into CSV, Parquet, SQLite or PostgreSQL.

Every load is verified by re-counting rows before a run is marked successful

Python, Streamlit, pandas, SQLAlchemy, SQLite, PostgreSQL, APScheduler, Docker, pytest, GitHub Actions

Built with guidance from an AI mentor.

What is inside
  • REST API sources with API key or bearer auth, four pagination styles, retries and rate-limit handling. CSV, JSON and Parquet uploads.
  • 13 transformation steps with a safe expression language (no eval), plus data-quality rules that reject bad rows or stop the run.
  • Replace, append or upsert loads in one transaction. A failed replace keeps the old table.
  • Run history, schedules, a command line interface, Docker Compose, and a test suite that runs in GitHub Actions.
